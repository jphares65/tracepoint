**Correction to D-01 (first pass said "no native app").** A native iOS/Android client exists. Its source is not in any repo. It registers `tracepoint://`, with `tracepoint://auth` as the auth callback. The RC adds two pieces so the native in-app scanner can resolve printed labels:
- `POST /api/mobile/qr/resolve` (`app/api/mobile/qr/resolve/route.ts`)
- `parseTracePointQrValue` (`lib/tracepoint/qr-identifiers.ts:10-19`)

It also fixes the 500s on non-UUID handles (B5), the existence disclosure (F4/F6b), and the "every vehicle scan denied" bug (F5). So **printed `tracepoint://vehicle|equipment/<id>` labels now work, but only inside the native app.** Limits that remain:
- A phone's stock camera or browser without the app still cannot open them. Whether an installed app also receives the OS-level scheme hand-off for `vehicle/` and `equipment/` paths is **Suspected/unknown**.
- Label generation is unchanged (`qr-identifiers.ts:3-7`). No HTTPS form exists, and HTTPS values still get 400 by design (B5).
- The web copy "Scan with a mobile device to open this vehicle" (`components/TracePointQrLabel.tsx:166`) is still misleading for web-only agencies or users.

The OA owns this as **FLT-04 / ARM-01**, with status "partly corrected".

**Notable RC changes in scope**
1. **Vehicle documents (D-34 fixed).** Four `window.prompt`s became an inline upload form: file, title, type select, date input, Edit, Replace and Archive (`[vehicleId]/page.tsx:59-63, 82`).
2. **Critical safety hold (F3/F6a).** The Manage Status card shows the hold, its source and since-date, names any blocking work order, and offers Clear Safety Hold through a `window.prompt` (`[vehicleId]/page.tsx:65, 78`). The FleetRules copy now says holds "always apply" (`settings/fleet/FleetRulesPanel.tsx:131, 139`). The hold is visible only on that one card (D-60).
3. **Fleet integrity (B4).**
   - Overrides can only escalate.
   - Odometer only moves forward. Lowering mileage in the vehicle form now triggers a `window.prompt` for a correction reason (`fleet-management/page.tsx:497-506`).
   - Inspection responses carry `audit: {status, message}`. The web UI ignores it (D-58).
4. **Fleet authorization (F2).** One inspection-eligibility rule (`canSubmitFleetInspection`, `lib/tracepoint/fleet-server.ts:71`), and inspectors no longer receive cost data. The UI still has no `canInspect` (D-11).
5. **Separated custody (B9).** Equipment held by inactive members now shows "Name (inactive)" in red, both in the table and in readiness (`equipment/page.tsx:1389-1390`, `lib/equipment/officer-assignments.ts:28-46`). OOS and Remove now require a reason (`equipment/page.tsx:990-998`, plus a labelled "Reason (required)" field in the edit form at ~`:2505-2515`).
6. **Shared date helpers.** `lib/format/date` (`formatDate`, `formatDateTime`) replaced 3 local copies (Consolidation 4 is done for these three pages).
7. **Help.** The Fleet article is now "Live" (`help/help-content.ts:673-689`).
8. **NEW module `/inventory`** (`app/inventory/page.tsx`, `InventoryCheckoutForm.tsx`, `OutstandingCheckouts.tsx`). It covers pooled and consumable stock: items, managed locations, receive and move, temporary checkout to an officer, unit or vehicle with a due date, partial and full returns, and an overdue flag. It is gated by `view_inventory`, `manage_inventory` or `adjust_inventory` (`lib/tracepoint/permissions.ts:61-63, 91`). Checkout and return need `adjust_inventory` (`app/api/inventory/checkouts/route.ts:5`).
   - The OA does not cover it, so findings D-62 – D-70 are all UX-unique.
   - It is a staff-operated counter workflow, not officer self-service.
   - It does not touch serialized `/equipment` custody (D-72).
9. **NEW `SecureStorageLocationsPanel`** (Settings → armory rules, "Secure Storage", `settings/page.tsx:4078-4080`). See D-71.

**Unchanged in RC:** `QuickInspectionPanel.tsx` (only the date helper changed), `FleetWorkOrderDialog.tsx`, `FleetEquipmentDialog.tsx`, `TracePointQrLabel.tsx`, `EquipmentRulesPanel.tsx`, and FleetRulesPanel except two copy lines. Every finding on these files is Present at the same or ±1 line.

### QR entry points (RC)

1. The **Fleet list row** uses `TracePointQrLabel` in `compact viewOnly` mode (`fleet-management/page.tsx:979-992`). Users get View QR and Copy Link only.
2. The **Equipment asset detail modal** uses it in full mode, with Download PNG and Print Label (`equipment/page.tsx:2238`). Printing is not gated by role.
3. **Payload:** `buildTracePointQrValue()` is unchanged and produces `tracepoint://vehicle|equipment/<id>` (`qr-identifiers.ts:3-7`). The **new** inverse, `parseTracePointQrValue()` (`:10-19`), is used only server side.
4. **New server path, native client only:**
   - `POST /api/mobile/qr/resolve` returns one of:
     - `vehicle_inspection` (eligibility follows F2/F5);
     - `equipment_custody`, routed to `GET/POST /api/mobile/equipment/custody`;
     - `firearm_custody`;
     - 409 ambiguous / `unknown`.
   - The web app still has **no scanner** (no `BarcodeDetector`, `getUserMedia`, zxing or jsQR) and no web route for `tracepoint://`.
   - There is **still no `/equipment/[id]`** route: `app/equipment/` holds only `page.tsx`.
5. **Help:** the Fleet article is now "Live" and lists "qr" as a keyword, but it says nothing about how scanning works or that it needs the app (`help/help-content.ts:678`).

**How a scanned QR lands a user in the RC:**
- **Native app:** the in-app scanner reads the label, the app posts it to `/api/mobile/qr/resolve`, and the app opens the workflow. The native screens are not visible to us, so the tap count is unknown.
- **Stock phone camera, app not installed:** the camera decodes `tracepoint://…`, and nothing handles it, same as on main.
- **Web-only user:** no path. The web "Copy Link" copies the same `tracepoint://` string (`TracePointQrLabel.tsx:127`).

**Tap count: officer on a phone, web (vehicle inspection, no exceptions).** Unchanged from the first pass: about 8–9 taps plus typing. Quick Inspect still only switches the tab (`[vehicleId]/page.tsx:75`), and `?tab=` is still ignored (`:42`). Photos are still impossible on the web (D-05). The evidence API is reachable from the native client (`api/mobile/fleet/.../evidence/route.ts`).

**Tap count: serialized equipment checkout or check-in, web.** Unchanged. It is manager-only: Edit form → custody `<select>` → Save, about 6 taps. B9 now preserves custody shown for separated holders. The OA records that the native client is the intended UI for self-service equipment custody (R5, EQP-06), but this is unverified.

**Tap count: pooled stock checkout, `/inventory` (new, staff with `adjust_inventory`):**
1. Hamburger → Assets & Fleet → Inventory.
2. Scroll past the whole "Current inventory" list and "Outstanding checkouts" to "Temporary checkout" (`page.tsx:748-756`).
3. Item `<select>` → Source location `<select>` → Recipient type → type and pick the officer → quantity → (due date) → **Check out**.

That is about 10 taps plus typing, with no QR or scan entry.

**Tap count: return, `/inventory`:** Inventory → find the row (there is no search or filter on outstanding checkouts) → **Return** → **Return All**. That is about 4 taps plus scrolling.

### Observed patterns (RC delta)

- **Visual language.** Unchanged: dark slate cards, hard-coded colours, no tokens, and no shared Button, Modal or Badge.
  - `/inventory` adds a slightly different idiom: `rounded-lg`/`rounded-xl`, `bg-slate-900/40`, local `Panel`, `Label`, `Notice`, `ActionButton` and `Submit` components (`inventory/page.tsx:762-970`).
  - It is the first module in scope with real `<label>` wrappers and a card list instead of a wide table, which makes it mobile-friendlier than Equipment and Fleet.
- **Modals.** Still 8 hand-rolled ones. `/inventory` uses inline panels, not modals.
- **Native dialogs** in the RC:
  - `window.prompt`: vehicle status ×2, Clear Safety Hold, mileage correction, equipment OOS/Remove reason. The 4 document prompts were removed.
  - `window.confirm`: type delete/archive ×2, document archive.
- **Dates.** `formatDate`/`formatDateTime` are now shared in the Fleet and Equipment pages. `/inventory` reintroduces raw `toLocaleString()` (`OutstandingCheckouts.tsx:193, 198`).
- **Dev and preview copy** still ships: Fleet "Local preview mode" (`fleet-management/page.tsx:385-389`, `[vehicleId]/page.tsx:56`), and Inventory's "Vehicle, room, and bin targets are reserved for a later phase." (`inventory/page.tsx:662-665`).
- **Three "location" models now coexist:**
  - Equipment's free-text `assigned_location`;
  - Inventory's managed `inventory_locations`;
  - Armory Secure Storage locations.

Locations: `[vehicleId]/page.tsx:63-65`, `fleet-management/page.tsx:502, 537`, `equipment/page.tsx:825, 835, 992`.

### Workflow simplification opportunities (no new features; reduce steps)

- **QR → inspection.** For native users the resolver now does the work. For web users nothing changed: fix the copy (D-01), make Quick Inspect open the form and honour `?tab=` (D-06), and print from the vehicle page (D-03).
- **Officers' "my equipment".** Default to the readiness card (D-17), de-duplicate rows (D-22), and show pooled checkouts held by the officer on the same card (D-72).
- **Manager triage.** Add a "Safety hold / Failed / Open work" filter to the fleet list (D-13, D-60), and show failed items inline (D-12).
- **Status changes in one place.** Remove the inline row select (D-15). Disable status buttons while a hold is active (D-60).
- **Inspection outcome.** Report the real readiness and audit outcome in one message (D-58), and close the form when the server says the record was saved (D-59).
- **Inventory counter checkout (about 10 taps → about 6).**
  - Put the checkout form first, or open it from a row ("Check out" on a balance row pre-fills item and location).
  - Auto-select a single location, add due presets, and default the recipient type to the last one used (D-66).
- **Inventory return.** Add a search/filter and "overdue first" sort, show names (D-62), and confirm Return All (D-67).
- **Requirement setup** in one place (D-23, D-24). Move the type manager off the daily page (D-41).
- **Issue report.** Require an explicit operability choice (D-10), and wire up or remove "Limited use" (D-09).
