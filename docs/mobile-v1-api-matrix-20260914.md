# TracePoint Mobile V1 API Matrix

This contract is AWS-native only. Cognito access tokens are accepted as `Authorization: Bearer`; the server verifies signature, issuer, client, token type, lifetime, live Cognito state, and the active TracePoint identity link. `X-TracePoint-Department-Id` is only a requested context: PostgreSQL membership, RBAC, and RLS remain authoritative.

| Mobile action | Method and endpoint | Authentication / permission | Tenant scope | Request | Response | Idempotency and failure modes |
| --- | --- | --- | --- | --- | --- | --- |
| Current session and department selection | `GET /api/mobile/session` | Cognito access-token bearer; active TracePoint identity | Server-resolved memberships; optional `X-TracePoint-Department-Id` is validated, never trusted | No body | Safe identity, memberships, selected access context, roles, permissions, platform-admin flag, token expiry | Read-only; `selectionRequired` when multiple departments exist; `401` invalid/inactive/unmapped session; `403` forged or inactive department |
| Active Range Days | `GET /api/pilot/range-workspace` | Bearer session; Range feature and membership | Active server-selected department | No body | Existing department workspace, from which the client reads `rangeDays` | Read-only; `401`/`403`; existing compatibility endpoint remains the list source |
| Range Day summary / roster / drills / results / resume | `GET /api/mobile/range-days/{rangeDayId}` | Bearer session; Range or Qualifications feature | Range Day must exist inside the selected department workspace | No body | Mobile summary, attendance counts, roster/personnel, ordered drills/library, existing results, resume drill/run, permissions, revision timestamp | Read-only and `no-store`; `401`, `403`, `404`, sanitized `500` |
| Individual attendance | `POST /api/mobile/range-days/{rangeDayId}` | `manage_range_days` or department administration | Roster entry must belong to the selected Range Day | `{type:"attendance",operationId,rosterEntryId,attended}` | Updated mobile summary and `alreadyApplied` | Operation ID makes replay idempotent; optimistic revision; `400`, `403`, `404`, retryable `409`, sanitized `500` |
| Bulk attendance | Same endpoint | `manage_range_days` or department administration | All roster entries remain in the selected tenant workspace | `{type:"bulk-attendance",operationId,attended}` | Updated summary | Mark-all-present/absent is idempotent; same failures as individual attendance |
| Add/remove roster member | Same endpoint | `manage_range_days` | Added officer must be an active member of the selected department | `{type:"add-roster",operationId,value:{id,officerId,assignedFirearmIds,attended}}` or `{type:"remove-roster",operationId,rosterEntryId}` | Updated roster summary | Duplicate operation is accepted once; history-bearing entries cannot be removed; `403` foreign/inactive member, `409` concurrent update |
| Drill list and detail | Included in Range Day `GET` | Range view authority | Only drills assigned to the selected tenant's Range Day | No body | Ordered drill payload with server-side library details, formats, standards and existing-result state | Read-only; no duplicate client scoring rules |
| Add/reorder/remove drills | Range Day `POST` | `manage_range_days` | Templates and assignments must belong to the selected department workspace | `add-drill`, `reorder-drills`, or `remove-drill` plus unique `operationId` | Updated ordered drills and summary | Add copies an active server template; exact-order validation; scored drills cannot be removed; idempotent retry and `409` concurrency response |
| Scoring roster / existing result retrieval | Included in Range Day `GET` | Range view plus server-provided `canScore` flag | Selected Range Day and department only | No body | Roster, existing results, last drill/run, and score authority | Read-only; unauthorized mutation remains blocked even if UI state is forged |
| Submit score/result | Range Day `POST` | `score_range_days`, `manage_qualifications`, or `manage_range_days` | Officer and drill must belong to the selected Range Day | `{type:"save-score",operationId,value:{id,drillId,officerId,runNumber,score,timeSeconds,hitCount,completed,notes}}` | Updated summary/result state | Server calculates automatic-format pass/fail; operation ID prevents duplicates; encrypted client queue retries; `400`, `403`, `404`, `409`, sanitized `500` |
| Resume scoring | Included in Range Day `GET` | Range view; scoring action separately requires score authority | Derived only from existing records in the selected Range Day | No body | Last scoring drill and run when present | No fragile server session is created; client preserves selected Range Day/drill/run and encrypted drafts |
| Vehicle list / QR lookup | `GET /api/fleet/vehicles` and `GET /api/fleet/vehicles/{vehicleId}` | Bearer session; granular Fleet view authority | Server-selected department and Fleet RLS | Safe path identifier only | Vehicle, inspection rules, equipment, inspections and work orders | Read-only; foreign/unknown identifiers return denied/not-found without object enumeration |
| Submit vehicle inspection | `POST /api/fleet/vehicles/{vehicleId}/inspections` | Inspector role or granular Fleet inspection authority | Vehicle must belong to selected department | Inspection type, mileage/hours, notes and bounded checklist | Saved inspection and any existing defect/work-order outcome | Client locks duplicate taps and retains draft; server validation errors remain explicit; media failure does not discard the saved inspection |
| Inspection evidence authorization | `POST /api/mobile/fleet/vehicles/{vehicleId}/inspections/{inspectionId}/evidence/initiate` | Inspector, configured inspection role, or granular Fleet permission | Vehicle and inspection are loaded from the selected tenant | Checklist item, safe filename, allowed MIME type, exact size | Opaque signed intent, unique evidence ID, 60-second presigned PUT and required headers | Rejects arbitrary keys, missing relation, unsupported type, empty/over-25-MB file, cross-tenant access; signed intent expires after 120 seconds |
| Inspection evidence confirmation | Sibling `POST .../evidence/confirm` | Same authenticated identity and inspection authority | Intent binds tenant, vehicle, inspection, checklist item, object and uploader | Opaque signed intent | Confirmed safe metadata and `alreadyConfirmed` | Idempotent; S3 HEAD must match exact size/type/tenant/object metadata and KMS encryption; missing upload, stale/tampered intent or mismatch fails closed; mismatched object is deleted |
| Inspection evidence retrieval | `GET .../evidence/{evidenceId}` | Tenant membership plus granular Fleet view/management authority | Evidence is rediscovered from server inspection metadata | Safe path IDs only | Fresh 60-second signed view URL and safe metadata | Confirmed objects only; path/key is revalidated, object remains private; `401`, `403`, `404` |

Inspection media uses the existing `fleet_vehicle_inspections.checklist` JSON document. This avoids a new schema migration while preserving the existing Fleet RLS boundary. No bucket name, AWS credential, Supabase endpoint, or provider secret is exposed to the client.

Mobile range mutations deliberately do not use the older whole-workspace `PUT`. Each action is whitelisted, authorized independently, checked against finalized history, and committed only if the workspace revision is unchanged.
