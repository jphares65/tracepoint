# Authentication portability implementation

The central server-access resolver now delegates verified-user retrieval to a server-only provider boundary. Its live selector accepts Supabase only and still calls the request-scoped Supabase getUser API. Existing profile UUIDs, department memberships, permission resolution and display metadata are preserved. No production authentication setting or user was changed.

Prepared Cognito code verifies RSA-signed access tokens with the official AWS JWT verification library, exact issuer/pool/client binding, expiry and a maximum 15-minute lifetime. It requires an active server-maintained issuer/subject mapping to an existing TracePoint UUID and a mandatory session-activity check. Unknown, revoked or unavailable mapping/session state denies authentication. Email, custom user-ID/department claims and Cognito groups cannot grant TracePoint roles. Department authorization resolves permissions from trusted membership lookup using the stable UUID.

Migration 202609050006 adds server-only identity links, pending by default, with uniqueness constraints and no client access. It imports or activates nobody. Existing profiles still reference Supabase auth.users: this schema is a mapping foundation, not removal of that dependency. Invite/activation/password-reset/logout ports are defined but not implemented for Cognito; no callback/session-cookie flow, Cognito pool, migration trigger or provider switch is deployed.

Validation: eight authentication tests cover actual signed JWTs, issuer/client/type/expiry/tampering rejection, claim-based privilege escalation denial, membership isolation, persistent activation/revocation, duplicate links and client mutation denial. Two mapping-reconciliation tests preserve user UUID and membership/role fingerprints while rejecting role drift and duplicate/reassigned links. The full application suite passed 158 tests; TypeScript and configured Next production build passed. New authentication files pass lint. The touched legacy server-access file retains nine pre-existing any errors and three unused-variable warnings.

Clean standard PostgreSQL bootstrap passed all 62 migrations. The optional dump/restore first failed because the embedded package omits pg_dump; using the existing trusted local client tools via TRACEPOINT_PG_BIN completed all-table count/checksum/RLS reconciliation in 2037 ms. This is local restore evidence, not an AWS PostgreSQL or production recovery claim.

Local mapping review command: node scripts/authentication-mapping-manifest.mjs BEFORE.json AFTER.json. Inputs contain profile UUIDs, memberships and provider links; output contains counts and fingerprints, never identity values. It does not prove control of an external identity or authorize activation. Production user export/transfer remains prohibited in this run.

Remaining live gates: Cognito infrastructure and client settings, supported invite/activation/reset/logout implementations, server session/revocation persistence, callback/PKCE/CSRF integration, database/RLS compatibility for Cognito sessions, authoritative identity migration proof and full live tenant/permission acceptance. [AWS JWT verifier](https://github.com/awslabs/aws-jwt-verify) and [Cognito token verification](https://docs.aws.amazon.com/cognito/latest/developerguide/amazon-cognito-user-pools-using-tokens-verifying-a-jwt.html) define the token checks.
