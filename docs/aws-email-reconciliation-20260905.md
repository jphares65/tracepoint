# Email outbox reconciliation gate

The dispatcher previously returned uncertain sends to Pending, including a send accepted by Brevo followed by failed database bookkeeping. It now retries only an explicit 429 rejection. Transport errors, server errors, malformed success without an acceptance ID and post-acceptance persistence failures become terminal Failed queue entries requiring reconciliation. Known provider message IDs are retained where persistence is available. A compare-and-set update cannot overwrite a row already recorded Sent. If the failure marker itself cannot persist, the claimed row remains Processing and is not automatically reclaimed.

The shared outcome handler also recognizes the prepared SES adapter's uncertain acceptance and suppression failures. It emits sanitized operator messages; provider diagnostics and recipient content are not stored as the new failure reason. Brevo remains active; SES remains disabled. An operator must verify provider events before manually resetting a failed/processing entry. This change deliberately favors avoiding duplicate transactional mail over automatic resend after uncertainty.

Validation: 29 email tests (including the final missing-ID case), 179 broad application tests plus that focused case, 39 script tests, TypeScript, changed-file lint and production Next.js build pass. Tests cover accepted-send/bookkeeping failure, transport ambiguity, server errors, missing acceptance IDs, explicit throttling, suppression and confirmed persistence. No live queue resend has been performed. Deployment and live delivery evidence will follow the guarded OIDC release.
