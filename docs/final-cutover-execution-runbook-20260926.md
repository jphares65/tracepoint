# TracePoint final cutover execution runbook (draft; execution NOT authorized)

This is an operator checklist, not a command to activate the production write freeze or switch public authority. The source of truth for gate status is the dated proof ledger and addendum. Any failed or unknown gate is **NO-GO**. Record exact resource IDs, image digests, artifact VersionIds, timestamps, operator, approver, and sanitized command output in the execution record before proceeding.

## Cutover-commence decision versus cutover execution

**Before maintenance may begin:** require rehearsed source fence and abort/unfreeze, immutable capture/attestation, atomic import and full relational/object reconciliation, Cognito/session/recovery, SES application-originated delivery/bounce/complaint correlation in an isolated final-shaped path, direct authenticated bidirectional API tenant-negative evidence, a healthy isolated AWS-native managed service, a pullable rollback image/task definition, tested data-authority rollback/write continuity, human alerting, backup restore, and a reviewed executable worker-switch/rollback artifact. Do not substitute a planned step for a rehearsed mechanism. A failed or missing prerequisite is `CUTOVER COMMENCE NO-GO`.

**Only during the approved maintenance window:** announce maintenance, fence live source writes, capture the actual final frozen source, apply and reconcile its final delta, stage/activate the exact production Cognito cohort, deploy the approved AWS-native candidate, switch the live SES feedback worker to final-RDS authority, run pre-traffic smoke, obtain a separate human authority-switch GO, route customer traffic to AWS, run post-switch smoke and a bounded write/read-back, then monitor. These are `CUTOVER-EXECUTION STEP`s, each with the stop/abort gate below. They need not be completed to authorize *commencement*; none is authorized by this document alone.

## 6. Abort and rollback decision

Before any AWS-only write: route back to the known-good bridge revision, verify public health, and restore source writes/dispatcher only after verifying the source remained authoritative and no AWS delta exists. After an AWS-only write: **do not simply repoint traffic to Supabase**. Stop AWS writes, preserve both sides and a new RDS recovery point, enumerate and reconcile the complete AWS-only relational/object/identity delta, replay only reviewed source-compatible writes while source remains externally fenced, verify audit and tenant parity, then restore bridge authority and source writes in a single-owner sequence. If complete safe replay is not possible, keep AWS fenced and invoke incident recovery; never create dual writers or discard the delta. The bounded one-record rehearsal is evidence of the mechanism, not blanket approval for arbitrary production replay.
