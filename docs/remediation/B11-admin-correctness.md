## Native client contract (code not available)

- `/api/mobile/*` is untouched. No response shape changed anywhere.
- **`POST /api/settings/data`:** additive. It accepts a new command, `rpc: "save_department_member"`, whose args are the union of the three existing commands' args. The three existing commands behave as before.
- **`POST /api/settings/users/invite`:**
  - Inviting an email that already exists now returns **409** with a message (Cognito: before, raw **500**).
  - Inviting someone who is already a member of the agency returns **409** (bridge: before, **200**, which overwrote and reactivated).
  - Known Cognito refusals return 400 or 403 instead of 500.
  - The body is still `{ error }`.
- **Admin routes' 500 bodies:** invite, activation, password reset, assign password, personnel import, Platform administrator, super-admin and Support Mode (bridge) now carry a fixed message instead of the database or provider text. The status and the `{ error }` shape are unchanged. A client that displayed `error` shows the fixed text; no client should parse it.
- **CSV:** the agency-training event report (`GET /api/agency-training/events/{id}/report`) prefixes `'` to cells that start with `= + - @`, a tab or CR, and writes finite numbers unquoted. The column order and headers are unchanged.

## Deferred / owner decisions

- **Armory/firearm backups (33 files** under `src/app/api/armory`, `src/app/firearms` and `ArmoryWorkspaceNav.tsx.backup-*`) were left in place because B8 is changing that area in parallel. Delete them after B8 merges; nothing imports them. `scripts/repository-hygiene.test.mjs` excludes exactly those paths, so remove the exclusion then.
- **ADM-30 remainder, not in the B11 plan:** the empty `docs/AUTH_SETUP.md`, create-next-app assets in `public/`, demo data in `training-alerts.ts`, and the orphan `/settings/command-dashboard-analytics` page.
- **ADM-20 bridge mode:** the Supabase bridge has no request transaction. Making it atomic needs a wrapper SQL function in the Supabase lineage. Production is AWS-native, so this was not done.
- **ADM-19, Cognito:** Settings invite cannot attach a person who already has a TracePoint account from another agency. The 409 points to personnel import, which is the only attach path. Adding an attach option to invite is a capability, not a fix.
- **ADM-23:**
  - Fleet, Agency Training and Inventory have no feature-catalog codes, so they are gated by permission only. Adding codes is a data and entitlement decision.
  - Layouts still redirect to Home without a message when a module is off. The audit's `/unauthorized?reason=feature` would be a UX change.
- **ADM-32 residual:** 63 other API route files still return `error.message` from a database or provider error in some path. Examples are module routes such as the agency-training report and notification preferences. B11 covered the admin and onboarding APIs named in R6. Applying `unexpectedErrorResponse` elsewhere is mechanical but touches other batches' files (B6 is restructuring notifications). Separately, `/api/settings/data` replaces even intentional SQL messages ("Only a department Administrator may modify an Administrator account.") with "The settings operation could not be completed."; this was not changed.
- **ADM-07:** if staging step 3(b) shows that invited users cannot receive a recovery code, decide whether first-login activation should also mark the Cognito email verified.
- **ADM-10:** an agency with Qualifications on and Range & Training off still sees the Qualification Readiness card computed from no data. The summary endpoint it uses requires Range & Training. This is a separate design gap, not a load failure.
